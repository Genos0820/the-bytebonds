One8Data Databricks APIs

A native Databricks app that turns Unity Catalog tables into governed REST APIs, with no code.

Visit live site

The challenge

Exposing warehouse data as an API usually means a shared service account — which quietly bypasses the access rules the data team spent months defining. The goal was APIs where every call runs as the caller's own Databricks identity, so Unity Catalog permissions keep applying.

What we built

We built it as a native Databricks app that runs inside the customer's own workspace, so data never leaves their boundary. A no-code dataset builder turns Unity Catalog tables into REST endpoints, and the engine is deliberately read-only for now — a smaller surface to secure while the model proves itself.

Why we built it this way

The easy version of this is one service account with broad read access and an API key per consumer. It ships in a week, and it quietly undoes whatever the data team decided about who can see what. We took the slower route: every query runs as the caller's own Databricks identity, so Unity Catalog grants are still the thing deciding the answer. That also keeps us from becoming the security model by accident — we aren't holding permissions, we're passing them through. The engine is read-only for now. That's a choice rather than a gap: a smaller surface is easier to be certain about while the approach proves itself.
